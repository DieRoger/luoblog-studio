# CONTENT_STRATEGY.md

# Content Mission

The goal of this blog is not to teach APIs.

The goal is to document the complete engineering journey of building reliable AI systems.

Every article should contribute to a long-term knowledge base.

Readers should follow the evolution of the project rather than isolated tutorials.

---

# Personal Brand

Theme

Building Reliable AI Systems

Four Pillars

- Evidence
- Evaluation
- Observability
- Human Control

Every article should relate to at least one pillar.

---

# Target Audience

Primary readers

- AI Engineers
- Backend Engineers
- LLM Engineers
- Graduate Students
- AI Product Builders

Assume readers already understand programming basics.

Focus on engineering thinking.

# What Is Worth Writing

Write when:

A difficult bug is solved.

A major architectural decision is made.

A technology is replaced.

A performance bottleneck is found.

An experiment succeeds or fails.

Evaluation results reveal something interesting.

A lesson can help future developers.

---

# What Is NOT Worth Writing

Avoid articles like

How to install Python

FastAPI CRUD Tutorial

Git Basics

OpenAI API Introduction

Basic LangChain Demo

These are already saturated.

# Article Quality Checklist

Before publishing ask

Does this contain original engineering thinking?

Does it explain trade-offs?

Does it include evidence?

Would an experienced engineer learn something?

Could another developer avoid the same mistake?

If most answers are "No"

Do not publish.
